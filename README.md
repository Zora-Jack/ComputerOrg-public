# ComputerOrg

基于 Verilog 与 C 的计算机组成原理实践项目，记录从基础数字部件、多周期 RISC-V 处理器到流水线、Cache 和软硬件加速的设计与验证过程。

项目的主要工作包括处理器数据通路与控制逻辑实现、真实内存接口适配、流水线冒险处理、指令和数据 Cache，以及卷积程序、乘法指令扩展和硬件加速器控制。仓库同时保留测试程序、参考 Trace、批量测试脚本和实验记录。

## 项目概览

| 阶段 | 主要内容 |
|---|---|
| 基础部件 | ALU、寄存器堆、移位器 |
| 多周期处理器 | RISC-V 指令译码、状态机和数据通路 |
| 系统接口 | 真实内存握手、UART 输出、性能计数器 |
| 流水线优化 | IF / ID / EX / MEM / WB 五级流水线、前递、阻塞和分支控制 |
| 存储层次 | 四路组相联 I-Cache 与 D-Cache |
| 软硬件加速 | 定点卷积与池化、`mul` 指令扩展、DNN 加速器控制 |

当前自定义处理器采用 32 位 RISC-V 五级流水线结构。各阶段的实现思路、关键修改和调试经验在后文展开。

## 运行与验证入口

运行前需要按本地环境配置 GNU Make、相关仿真工具和交叉编译器。工具链路径在 `build_scripts/toolset.mk` 中设置；当前 Verilator 流程使用实验框架配套的工具包。

以流水线 CPU 的 Fibonacci 测试为例，先将 `PROJECT_NAME` 和 `BOARD_NAME` 设置为实际工程目录名与板卡配置名，再在仓库根目录执行：

```bash
make FPGA_PRJ="$PROJECT_NAME" FPGA_BD="$BOARD_NAME" \
  SIM_TARGET=custom_cpu \
  SIM_DUT=riscv32:turbo \
  WORKLOAD=simple_test:medium:fib \
  bhv_sim_verilator
```

批量测试入口为 `gen_trace.sh` 和 `check_trace.sh`。使用前需核对工程、板卡、DUT 和项目路径配置。不同阶段的测试程序使用的成功标志可能不同，应结合具体日志和测试配置判断结果。

## 个人实现与开发工作

### 1. 基础数字部件

这一阶段完成了处理器所需的 ALU、寄存器堆和移位器，并将它们作为后续 CPU 的公共模块复用。

ALU 支持加减法、按位逻辑运算以及有符号和无符号大小比较。加减法共用加法通路：减法通过对第二个操作数取反并加一实现；有符号比较结合减法结果的符号位与溢出信息，无符号比较利用进位信息判断大小。

寄存器堆采用两个组合读端口和一个同步写端口，对零号寄存器单独处理：读取始终返回零，写入被屏蔽。移位器支持逻辑左移、逻辑右移和算术右移，并通过显式的有符号转换保留算术右移的符号扩展行为。

### 2. 多周期 RISC-V 处理器

在基础部件之上，完成了由状态机驱动的多周期处理器。取指、译码、执行、访存和写回分阶段进行，通过中间寄存器保存指令、操作数、执行结果和读回数据。

主要工作包括指令字段与立即数提取、ALU 和移位器控制、分支条件判断，以及 `JAL`、`JALR` 的目标地址和返回地址处理。Load / Store 通路根据访问宽度与地址低位选择数据和字节写使能，并在读回时区分符号扩展和零扩展。

这一阶段采用较细的状态划分，将分支和跳转保留为独立状态，使各类指令的数据流和控制条件便于检查，也为后续真实内存接口扩展提供了基础。

### 3. 真实内存接口与系统功能

从理想内存切换到真实内存后，处理器需要处理请求接收和数据返回之间的延迟。这一阶段将取指、读数据流程拆分为请求与等待阶段，通过 Valid–Ready 握手推进状态机。

调试中重点解决了复位释放后首拍接口行为不一致的问题。加入明确的 `S_INIT` 初态，使复位阶段不发送取指请求，并按接口要求设置接收侧 Ready 信号；释放复位后再进入正常取指流程。

同时整理了握手、访存和写回相关的组合输出，使用连续赋值明确各状态下的控制条件。软件侧补全 UART 字符串输出，在发送 FIFO 未满时写入字符；增加周期计数器及其 MMIO 读取接口，以运行前后的计数差值测量程序开销。

### 4. 五级流水线与冒险处理

在多周期实现的基础上，将执行流程组织为 IF、ID、EX、MEM、WB 五个阶段。阶段间通过流水寄存器传递指令地址、操作数、目标寄存器和控制信息，并使用 Valid 位区分有效指令与气泡。

数据相关主要通过前递处理：EX 阶段可选择 EX/MEM 中已经就绪的结果或 MEM/WB 的写回结果，同拍写回的数据也可供 ID 阶段使用。对于尚未取得读回数据的 Load 指令，冒险检测按后继指令实际使用的源寄存器判断依赖，暂停前端并插入气泡。

分支和跳转在 EX 阶段产生重定向。除清空错误路径上的流水内容外，取指端还记录已经发出、尚未返回的请求，区分应丢弃的响应与需要暂存的有效响应。访存端记录请求是否已经完成握手，避免等待期间重复发送同一请求。

为了分析流水线的运行开销，增加了退休指令数、取指请求与响应、数据阻塞、访存等待、分支重定向等性能计数器，使优化效果可以通过具体事件和周期数解释。

### 5. 指令 Cache 与数据 Cache

I-Cache 和 D-Cache 均采用四路组相联结构，包含 8 个组，每条缓存行为 32 字节，单个 Cache 的数据容量为 1 KiB，不含 Tag 和状态位。每组维护替换指针，以轮转方式选择替换路。

I-Cache 完成请求地址保存、Tag 查询、命中数据选择以及 Miss 后的读请求、分拍接收和回填流程。一条缓存行由 8 个 32 位数据拍组成，回填完成后向处理器返回请求位置对应的指令。

D-Cache 在此基础上处理写入与脏块状态。当前实现采用写回和写分配：写命中按字节写使能更新缓存行并设置 Dirty 位；写 Miss 先取回缓存行，再合并写入数据；替换有效脏块时先完成整行写回，再读取新缓存行。

对于非缓存访问，数据通路绕过缓存，通过独立的读写流程访问内存或 MMIO，保留原请求的地址、写数据和字节写使能。

### 6. 卷积程序、乘法指令与加速器控制

DNN 实验围绕同一卷积与池化任务比较三种执行方式：软件移位加法乘法、CPU 原生 `mul` 指令，以及既有硬件加速器。

软件部分完成了二维卷积、Max Pooling 和结果比较。输入为单通道 28 × 28 图像，使用 20 个 5 × 5 卷积核；卷积输出为 20 × 24 × 24，再经 2 × 2、步幅为 2 的池化得到 20 × 12 × 12 的结果。

实现中使用统一的下标转换函数，将多维张量映射到一维内存。针对定点数计算，使用具有 10 位小数的 16 位数据和 32 位乘加累加值，写回前调整小数位。调试中修正了权重布局的理解：每个输出通道先存放 Bias，再存放卷积核权重。

处理器侧增加了 RV32M 中的 `mul` 指令。修改覆盖 ID 阶段的完整 `funct7` 提取、ID/EX 流水寄存器传递，以及 EX 阶段的指令识别和乘法结果选择，结果取乘积的低 32 位。

硬件加速路径的个人工作是控制软件与系统集成：通过 MMIO 写入启动信号、轮询完成状态并停止加速器，随后对输出进行检查。加速器硬件由既有平台提供。

### 7. 批量测试与性能分析

为减少逐个运行测试的重复操作，整理了批量测试与 Trace 检查脚本，覆盖 basic、medium、advanced、hello 和 microbench 共 40 个测试项。脚本逐项调用构建或仿真入口，并保存各测试的详细日志，便于在修改后检查回归结果和定位失败项。

测试关注指令执行结果、访存行为与退休信息，并结合性能计数器分析等待和阻塞开销。历史日志对应其记录时的代码与配置，当前版本的验证结果应以重新运行的测试为准。

## DNN 性能结果

以下数据来自实验记录中的同一卷积与池化任务，统计范围为程序内部性能计数器测得的核心执行周期。

| 执行方式 | 核心执行周期 | 相对纯软件基线的加速比 |
|---|---:|---:|
| 软件移位加法乘法 | 690,348,063 | 1× |
| CPU 原生 `mul` 指令 | 28,222,935 | 约 24.46× |
| DNN 硬件加速器 | 722,041 | 约 956.11× |

三种执行方式在记录的 FPGA 测试中得到正确输出。数据反映该任务、实现和测量范围下的周期差异；硬件加速器相对 CPU 原生乘法版本的加速比约为 39.09×。
